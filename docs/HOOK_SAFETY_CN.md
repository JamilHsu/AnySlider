# Hook 安全检查与回归测试（MegaMix+ v1.03）

## 本次已确认的问题

### Arcade 状态查询的寄存器契约

IDA v1.03：`+656535` 将 PV 指针放进 RCX，`+656538` 调用
`+2ACA80`，随后 `+656546` 读取 `[RCX+1Ch]`。
原生查询只通过 `+1D6640` 取得设置指针，再读出布尔值，不改写 RCX。
普通 C++ Hook 的日志、TLS 等代码会破坏标准 ABI 下的易失寄存器。

`src/mm_arcade_query_bridge.asm` 在任何 C++ 代码之前保存
RCX/RDX/R8–R11、XMM0–5，保留 EAX 返回值，并提供 shadow space、
16 字节调用对齐和 unwind 信息。它针对当前整数返回/SSE 使用场景，
不承诺保留 YMM/ZMM 高位或提供异常退出时的自定义易失寄存器恢复。

不要把这套规则直接用于所有函数：部分原生函数有调用者可见的寄存器副作用。
例如 `+2AB300` CabinetOutput setter 本身改写 RCX/RDX/R8/R9；现有
`LedSetterBridge` 额外保护 R10/R11 和 XMM，而不是套用 getter 的契约。

### PS 圆圈确认与已有 wrapper hook

原版 `+2AB260` 为 7 字节 LEA 加 5 字节尾 JMP。当前 mod 环境中，
入口被改为 `FF 24 25 abs32`，跳到托管代码，原版尾 JMP 仍完整。
原来的全字节校验导致圆圈确认降级为仅诊断（`ps-circle=0`）。

现在只对这个经过检查的入口允许此种链式形式：检查原版尾部、
读取间接指针并确认目标可执行，继续调用已有入口，不覆盖外部 hook。
六个迁移调用点仍逐一严格校验，并保留安装/卸载所有权检查。
可执行性检查不等于证明第三方代码的语义；当前组合已完成启动日志验证，
并由用户确认菜单操作正常。未知跳转形式仍拒绝安装。

## 统一的保守策略

`src/hook_validation.h` 用于 UI 公共 Action 入口、LED 捕获/恢复/诊断、
测试模式和触屏固定入口：

- 默认要求精确字节匹配，不自动追随任意跳转。
- 通过 ReadProcessMemory 检查可读性；不匹配时记录名称、RVA、
  第一个差异和入口字节，不写内存。
- 保留模块原有版本门槛和可选模块降级机制。
- 触屏补齐 v1.03 入口校验，并按 IDA 修正为无参数查询原型。
- 测试模式补齐 PollMenu、ManagerTick 两个 detour 入口的校验。
- 触屏 attach/detach 失败时 abort，不再用 commit 的结果覆盖失败。
- Arcade LED 未取得事务时直接返回，不 abort 其他模块的事务。

核心输入的特征扫描和 Windows API hooks 沿用原有机制，没有转换为
盲目的固定地址 fallback，也没有尝试覆盖未知第三方 hook。

## 检查范围与限制

此次检查覆盖 hook 安装路径和几个高风险原生函数的 IDA 反汇编，
不是对游戏所有调用点的完整寄存器活跃性证明。未发现新的崩溃证据时，
不把普通复杂函数一律改成自定义调用约定。

LED 诊断与 LED 恢复都涉及 `+42F490`；如果恢复先安装，诊断的严格
校验可能拒绝该入口。这是现有的安全降级，不应通过统一放宽匹配来绕过。
本次未重构诊断采样所有权，也未对触屏硬件和街机测试模式做实机验收。

## 测试

在 VS 的 **x64 Native Tools Command Prompt** 中执行：

```bat
tools\tests\run_hook_tests.cmd
```

覆盖：

1. 故意破坏易失寄存器的汇编实现，验证 Arcade 桥恢复寄存器、真假返回值、
   shadow space、栈对齐以及 RtlVirtualUnwind。
2. 原版/已知链式 wrapper 分类、未知字节修改拒绝、PS 类型确认/返回映射。
3. 统一校验器对匹配、差异、不可读页面、空指针、超长输入的处理，且不写入目标。

测试产物位于 `artifacts/`；测试不会修改游戏配置或存档。
Debug 和 Release x64 均需构建。菜单运行验证还应覆盖 ○确认/×返回、
暂停/继续；屏幕提示图标维持原样。
